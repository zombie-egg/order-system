一、怎么启动？

  1. 打开项目文件夹进入 D:\ppt\大学\收银平台项目。
  2. 双击 Start-Demo.cmd第一次启动可能需要安装依赖，请等待窗口显示 “SipPilot local demo is ready”。不要关闭这个黑色窗口。
  3. 看窗口打印的地址系统通常会自动打开三个网页。若没有自动打开，就复制窗口中的 Kiosk、Kitchen Display、Admin 地址到浏览器。
  4. 演示结束回到黑色启动窗口按 Ctrl+C，即可停止本次运行。
端口数字不一定相同：默认是 5173、5174、5175 和 8000。如果这些端口被占用，启动器会自动换成 15173、15174、15175、18001 等可用端口。请始终以启动窗口实际打印的地址为准。

二、为什么有三个网站？

因为真实门店里有三类不同的人在使用系统。把它们分开，既方便操作，也避免顾客进入员工或管理员功能。

1

Kiosk 顾客点单机

给顾客使用。类似麦当劳/KFC 的触摸点餐屏。顾客浏览饮品、选择杯型和牛奶、查看税费、提交订单、模拟刷卡，并看到取餐号。

2

Kitchen Display 制作看板

给吧台员工使用。员工接收已付款订单，依次操作“确认订单 → 开始制作 → 制作完成 → 顾客已取走”。系统只管理人工流程，不控制饮品机器。

3

Admin 管理后台

给店长和管理员使用。用于查看订单、销售数据、员工、商品价格、门店策略、退款、人工审核和审计记录。

四、推荐的完整演示流程

  1. 先连接 Kitchen Display打开 KDS 页面，填写窗口打印的 API 地址、Endpoint ID 和 Endpoint Key，再使用 demo-nl / demo-owner / DemoOwner!2026-NL 登录。保持这个页面开启，因为系统会用心跳确认确实有人可以人工制作。
  2. 打开 Kiosk 并配对填写相同 API 地址、窗口中的 Kiosk ID，以及固定 Kiosk Key。进入点单页面。
  3. 模拟顾客点单选择一种饮品，选择规格或牛奶，加入购物车，检查数量、价格和 VAT，然后点击确认订单并执行模拟付款。成功后会显示订单号/取餐号。
  4. 回到 KDS 制作订单新订单会出现在待处理区。依次点击 Acknowledge（确认）、Start preparing（开始制作）、Mark ready（制作完成）、Mark collected（已取走）。
  5. 登录 Admin 查看结果使用管理员账号登录。在 Dashboard 查看概览，在 Orders 查看订单，在 Reports 查看销售和履约统计，在 Audit 查看操作记录。
  6. 演示异常和人工审核（可选）再创建一笔订单，在 KDS 将其标为无法履约并填写原因。然后进入 Admin 的 Manual review 页面，接单并选择退款、重做或替代品等人工决定。

六、常见问题

提示 8000 端口被占用怎么办？

重新双击 Start-Demo.cmd。最新版会自动选择备用端口，无需手动 taskkill。看到黄色 Warning 不代表失败，继续等待最终地址即可。

Kiosk 提示暂时不能下单？

先确保 KDS 已完成设备连接并保持页面开启。真实商业流程不能在无人制作时继续收款，因此系统会检查 KDS 心跳。

网页打不开或数据没刷新？

确认启动窗口没有关闭；使用窗口最新打印的地址；然后按 Ctrl+F5 强制刷新网页。

这是正式支付吗？

不是。当前演示使用 Mock Payment Provider，只模拟支付成功/失败流程。接入 Adyen、Stripe 或 SumUp 及真实支付终端属于生产部署阶段。

会自动做饮品吗？

不会。本项目只负责点单、收付款、订单、人工制作看板和管理后台，不控制泵、阀、PLC、咖啡机或其他制饮硬件。
